너는 모바일 웹 2D 블록 생존 샌드박스 게임 「가나디: 잿빛 지구」의 구현 담당이다.

기존 마스터 사양과 AI 개발 통제 규칙을 따르고, 현재 기능과 저장 데이터를 유지하면서 아래 변경 사항을 구현하라. 구현 전에 현재 파일과 실제 동작을 확인하고, 이미 구현된 기능은 중복으로 만들지 않는다.

이 문서의 ‘확정 요구사항’을 우선한다. ‘권장 기본값’은 아직 확정되지 않은 수치를 위한 구현 기준이며, 변경할 경우 이유와 최종 적용값을 보고한다.

## 0. 작업 기준과 기존 기능 보호

### 현재 기준 배포본

현재 최신 작업 결과는 `ganadi-mobile-flex-web`이다. 실제 작업 폴더에 더 최신 수정본이 있다면 변경 내용을 비교해 최신 상태를 기준으로 삼는다.

최신 TypeScript 원본이 있는지 먼저 확인한다. 배포 번들과 별도 JavaScript 모듈만 존재한다면 그 사실을 명시하고, TypeScript 원본 빌드를 완료했다고 보고하지 않는다.

### 반드시 유지할 기존 기능

- PC 키보드·마우스 조작.
- 모바일 왼쪽 이동 스틱과 완화된 위쪽 점프 입력.
- 모바일 오른쪽 점프 버튼.
- 손가락을 따라 움직이는 조준 패드와 터치 종료 시 원위치 복귀.
- 이동·조준·점프·상호작용의 멀티터치 구분.
- 모바일 월드 화면 직접 터치로 조준점이 변경되지 않는 동작.
- 블록을 든 상태에서도 연속 채굴과 몬스터 공격이 가능한 동작.
- 설치 버튼을 눌렀을 때만 모바일 블록 설치.
- 상황별 상호작용 버튼.
- 문 개폐, 침대 수면, 상자 보관.
- 모닥불 연료·화력·조리 일시정지와 재개.
- 나뭇잎 통과와 수평 이동 속도 0.7배 적용.
- 권총·탄약·광물·동물·치와와 먹이 주기.
- 기존 저장과 구버전 월드 생성 호환.
- 화면 회전 안내, 전체화면 지원, 화면 비율 대응.
- 의도하지 않은 화면 확대가 발생하지 않는 동작.

### 유지할 전투 수치

다음 수치는 이번 환경 업데이트를 이유로 임의 변경하지 않는다.

| 대상 | 체력 | 기본 공격력 |
|---|---:|---:|
| 닭 | 8 | 0 |
| 치와와 | 10 | 5 |
| 들돼지 | 12 | 0 |
| 소 | 18 | 0 |
| 잿빛 멧돼지 | 48 | 8 |
| 미노타우르스 | 72 | 10 |

- 권총 기본 공격력 18, 사거리 12타일 유지.
- 정상 상태에서 체력이 가득 찬 멧돼지는 권총 3발, 미노타우르스는 4발에 처치된다.
- 햇빛 피해·폭주 상태 등 별도 피해와 배율이 적용되는 상황은 구분한다.
- 맨손·블록·재료·도구의 근접 사거리는 2타일, 창은 3타일 유지.
- 근접 공격의 대상 선택과 최종 피해 판정은 같은 기준을 사용한다.

## 1. 시작 위치를 양방향 탐험에 적합하게 변경

### 확정 요구사항

현재 새 게임에서 플레이어가 월드 왼쪽 끝에 가까이 시작해 사실상 오른쪽으로만 탐험하게 되는 문제를 개선한다.

- 새 게임 시작 위치를 월드 중앙 또는 중앙에 가까운 안전한 지표로 이동한다.
- 시작 위치에서 왼쪽과 오른쪽 모두 충분한 탐험 공간을 확보한다.
- 월드의 크기를 무한으로 바꾸는 작업은 아니다. 기존 좌우 경계는 유지한다.
- 시작 위치 주변에 즉시 빠지는 깊은 구덩이, 물속, 협곡 바닥, 블록 내부, 위험한 낙차가 없도록 한다.
- 플레이어 몸이 들어갈 공간과 발밑 지지 지형을 검증한다.
- 스폰 주변을 보정하더라도 넓은 지역을 부자연스럽게 평탄화하지 않는다.
- 시작 카메라와 청크 로딩도 새 스폰 위치에 맞춘다.
- 기존 저장의 플레이어 위치를 중앙으로 강제 이동하지 않는다.
- 사망·위치 초기화가 기존 시작 위치를 참조하는지 확인하고, 새 게임의 안전한 시작 지점과 일관되게 연결한다.

## 2. 보급 상자에 철 추가

### 확정 요구사항

- 보급 상자의 무작위 보상에 철을 추가한다.
- 철은 구리보다 희귀하게 유지한다.
- 기존 통조림·횃불·나무 조각·구리 보상을 불필요하게 제거하지 않는다.
- 상자마다 같은 시드와 위치에서 보상이 결정적으로 계산되는 기존 규칙을 유지한다.
- 저장·재접속·파괴 반복으로 보상이 복제되지 않게 한다.
- 기존 철 아이템 ID를 유지한다. 표시명이 철인데 내부 ID가 과거 이름인 경우, 호환을 깨뜨리며 이름을 바꾸지 않는다.

### 권장 기본값

- 일반 보급 상자: 철 1개, 독립 확률 10%.
- 구리 확률은 현재 30%를 유지한다.
- 광석 채굴이 무의미해질 정도로 철을 대량 지급하지 않는다.

### 추가 점검

현재 철 광석의 실제 채굴 보상이 철인지 확인한다. 블록 정의와 별도 전리품 테이블의 우선순위 때문에 구리 등 다른 보상으로 덮어써지고 있다면 수정한다.

## 3. 지표 지형 다양화

### 확정 요구사항

새 월드의 지표를 평탄한 구간 위주에서 다음 지형이 섞이는 형태로 개선한다.

- 집을 짓기 좋은 평지.
- 완만한 언덕.
- 주변보다 낮은 분지.
- 가끔 등장하는 절벽과 단차.
- 낮은 빈도로 등장하는 지상 호수·웅덩이.
- 드문 특별 장소가 배치될 수 있는 자연스러운 부지.

### 생성 규칙

- 큰 지형 변화와 작은 표면 변화를 서로 다른 크기의 노이즈로 조합한다.
- 전체가 톱니 모양이거나 몇 칸마다 급격한 벽이 생기는 지형을 피한다.
- 절벽이 있다는 이유로 초반 이동이 계속 막히지 않도록 평지·완만한 경로도 확보한다.
- 시작 지점 주변은 비교적 안전하고 이동하기 쉽게 구성한다.
- 같은 시드에서는 같은 지형이 생성된다.
- 청크 경계에서 지형이 끊기지 않는다.
- 기존 지표 바이옴의 나무 밀도와 분위기를 유지하면서 지형 변화와 결합한다.
- 구조물 배치를 위해 전체 월드를 인위적인 평지 띠로 만들지 않는다.

---

## 4. 깊은 균열에 실제 협곡 생성

### 확정 요구사항

깊은 균열을 단순히 깊이로 구분되는 일반 동굴이 아니라, 실제로 큰 낙차와 갈라진 지형을 가진 구역으로 개선한다.

- 기본적으로 기존 깊은 균열 적용 구간인 세로 좌표 100 이상을 사용한다.
- 세로로 깊거나 비스듬히 이어지는 협곡형 빈 공간을 생성한다.
- 양쪽 절벽, 중간 돌출부, 일부 발판을 둔다.
- 일부 협곡에 끊어진 목재 다리나 낡은 통행 흔적을 배치할 수 있게 한다.
- 플레이어가 다리를 설치하거나 우회·하강 경로를 만들어 탐험할 수 있게 한다.
- 모든 깊은 지하를 하나의 거대한 빈 공간으로 만들지 않는다.
- 일반 동굴과 좁은 통로도 함께 남긴다.
- 월드 경계와 바닥 기반암을 침범하지 않는다.
- 협곡 바닥 일부에는 물웅덩이 또는 지하 호수가 생성될 수 있다.
- 전용 보스나 새로운 적대 몬스터를 이번 작업에 임의로 추가하지 않는다.

### 권장 기본값

현재 유한 월드 크기를 기준으로 대형 협곡은 2~3개 정도로 시작하고, 실제 탐험 밀도에 따라 조정한다.

협곡 크기는 고정 템플릿 하나를 반복하지 말고 폭·깊이·기울기를 변화시킨다.

## 5. 지하 웅덩이와 동굴 호수

### 확정 요구사항

- 동굴 바닥의 작은 웅덩이와 일부 넓은 지하 호수를 추가한다.
- 물이 허공에 떠 있거나 천장에 붙은 직사각형 덩어리처럼 보이지 않게 한다.
- 주변 지형과 바닥을 고려해 물이 고인 형태로 생성한다.
- 호수 주변에는 이동할 수 있는 물가나 돌출 지형이 일부 존재하게 한다.
- 협곡·폐광·발광 이끼와 조합될 수 있으나, 모든 구조물이 물에 잠기지 않도록 한다.
- 깊은 동굴의 어둠은 유지한다.
- 물 표현 때문에 낮의 지표나 화면 전체 밝기가 잘못 바뀌지 않게 한다.

### 물 동작의 권장 1차 범위

물의 세부 물리 동작은 아직 확정되지 않았으므로 다음 범위를 권장한다.

- 고정된 수역을 먼저 구현한다.
- 물은 고체 블록으로 취급하지 않는다.
- 물속에서는 수평 이동이 느려지고, 점프 입력으로 위로 헤엄칠 수 있게 한다.
- PC와 모바일에서 물 밖으로 나올 수 있어야 한다.
- 수영 효과가 물 밖에서도 남지 않게 한다.
- 물을 담는 것만으로 호수 전체가 사라지지 않게 한다.
- 복잡한 유체 확산·물 압력·침수 전파는 이번 기본 범위에 포함하지 않는다.
- 산소 게이지와 익사는 별도 요청이 없으면 추가하지 않는다.

정적인 물을 선택했을 경우 지형을 파괴했을 때 물이 어떻게 남는지 명확하게 정하고 결과에 보고한다.

## 6. 폐광을 여러 갈래 구조로 확장

### 확정 요구사항

현재 가로 20칸 × 세로 8칸의 단일 폐광 구조를 여러 공간이 연결되는 형태로 확장한다.

구성 요소:

- 가로 갱도.
- 위아래를 연결하는 수직 통로.
- 작은 창고와 작업 공간.
- 원목 지지대와 판자 구조물.
- 잔해로 막힌 일부 구간.
- 보급 상자가 있는 탐험 보상 공간.

### 생성 규칙

- 동일한 방 하나만 반복하지 않고 여러 모듈을 연결한다.
- 연결되는 통로 사이에 잘못된 벽이나 빈틈이 생기지 않도록 한다.
- 모든 방이 처음부터 열려 있을 필요는 없지만, 일부는 채굴로 연결할 수 있게 한다.
- 수직 통로는 계단식 발판 등 현재 조작으로 이동 가능한 구조를 사용한다.
- 사다리나 광산 수레 시스템을 별도 요구 없이 추가하지 않는다.
- 협곡을 가로지르는 일부 연결부는 끊어진 다리로 표현할 수 있다.
- 기반암과 월드 바깥을 침범하지 않는다.
- 청크 경계에서도 방과 통로가 동일하게 이어진다.
- 물과 구조물의 생성 우선순위를 명확하게 정한다.
- 보급 상자 수를 확장된 방 수만큼 무제한 늘리지 않는다.
- 폐광은 발견할 가치가 있지만 월드 전체에 지나치게 흔하지 않게 한다.

### 권장 기본값

- 월드당 폐광 단지 1개.
- 연결 모듈 4~7개.
- 보급 상자 총 3~5개.
- 규모와 실제 플레이 시간을 확인하고 최종 수치를 보고한다.

## 7. 지상의 드문 특별 장소

### 확정 요구사항

지상에 낮은 빈도로 다음 장소를 추가한다.

1. 작은 야영지.
2. 외딴 오두막.
3. 무너진 탑.

### 장소별 특징

작은 야영지:
- 간단한 목재 흔적과 모닥불 등으로 구성.
- 생성된 모닥불에 무한 연료를 주지 않는다.

외딴 오두막:
- 작은 실내와 출입구를 갖춘다.
- 완전히 막힌 공간이라면 방사능 먼지를 피할 수 있는 장소로 활용 가능하다.
- 문이 생성된다면 기존 다중 칸 문 연결·개폐·저장 규칙을 사용한다.

무너진 탑:
- 일부 벽과 층이 무너진 수직 구조.
- 발판을 이용해 올라가거나 보수해서 탐험할 수 있다.
- 무너진 구멍이 있는 탑을 자동으로 완전한 대피소로 판정하지 않는다.

### 공통 규칙

- 멀리서도 서로 구별되는 외형을 사용한다.
- 보급 상자를 모든 장소에 반드시 배치하지 않는다.
- 지형·호수·다른 구조물과 충돌하지 않게 한다.
- 시작 위치 바로 옆에 희귀 보상을 몰아두지 않는다.
- 기존 구조물과 함께 고려해 충분한 간격을 둔다.

### 권장 기본값

현재 월드 크기에서 추가 특별 장소는 총 2~4곳 정도로 시작한다. 각 종류를 매번 전부 강제로 생성할 필요는 없다.

## 8. 치와와 외형과 상태별 표정 개선

### 확정 요구사항

현재 치와와가 치와와처럼 보이지 않는 문제를 개선한다.

공통 특징:
- 큰 직립 귀.
- 둥근 머리.
- 짧은 주둥이.
- 작은 몸과 가는 다리.
- 치와와로 알아볼 수 있는 몸 비율과 꼬리.

먹이를 주기 전:
- 날카로운 눈매.
- 드러낸 이빨이나 으르렁거리는 입 모양.
- 긴장한 자세.
- 적대 상태가 시각적으로 드러나야 한다.

먹이를 준 후:
- 부드러운 눈매.
- 다문 입 또는 편안한 표정.
- 긴장이 풀린 자세.
- 기존 목줄 등 길들임 표시를 유지하거나 개선한다.

### 동작 유지

- 고기 1개를 주면 해당 개체만 얌전해진다.
- 얌전해진 상태는 저장과 재접속 후에도 유지한다.
- 얌전해진 치와와는 플레이어를 공격하지 않는다.
- 다른 치와와의 적대 상태까지 바꾸지 않는다.
- 피격 시 붉은 표시와 적대·온순 표정이 서로 충돌하지 않게 한다.
- 색만 바꾸지 말고 눈·입·자세로도 상태를 구별한다.
- 외형을 개선하면서 공격·먹이 주기의 몸 판정이 어긋나지 않게 한다.
- 따라오기·경호·번식 기능은 이번 범위에 추가하지 않는다.

## 9. 방사능 먼지 이벤트

### 확정 요구사항

게임 시작 직후부터 발생하지 않고, 약 3일간의 준비 기간 후 주기적으로 방사능 먼지가 지나가게 한다.

- 새 게임 시작 후 게임 시간 약 3일간은 발생하지 않는다.
- 이후 약 하루 간격으로 발생한다.
- 발생 전 대피 안내를 제공한다.
- 진행 중 화면 효과와 상태 표시를 제공한다.
- 효과 때문에 조준점·몬스터·발판·버튼을 알아보기 어려울 정도로 화면을 가리지 않는다.
- 모바일 성능을 고려해 파티클 개수를 제한한다.
- 이벤트 시작과 종료 시 화면 확대를 사용하지 않는다.

### 시간 관리

- 현재 낮·밤 주기를 기준으로 누적 경과 일수를 관리한다.
- 하루 안에서 반복되는 시각과 전체 누적 시간을 구분한다.
- 일시정지와 앱 비활성 시간에는 게임 시간이 진행되지 않는다.
- 수면으로 아침을 맞으면 경과 일수도 정상 반영한다.
- 수면으로 건너뛴 시간의 방사능 피해를 한꺼번에 부과하지 않는다.
- 수면 후 이벤트 일정이 중복되거나 영구히 사라지지 않게 한다.
- 이벤트 상태와 다음 발생 시간을 저장한다.
- 새로고침으로 준비 기간이나 발생 간격을 계속 초기화할 수 없게 한다.

### 권장 기본값

- 기존 하루 600초 기준 유지.
- 누적 게임 시간 1,800초에 첫 방사능 먼지 시작.
- 이후 시작 시점 간격 600초.
- 시작 30초 전 예고.
- 먼지 지속 시간 60초.
- 기존 저장에 누적 일수 정보가 없다면 안전한 이주 기준을 정하고, 불러오자마자 예고 없이 피해를 주지 않는다.

## 10. 방사능 노출과 디버프

### 확정 요구사항

- 방사능 먼지가 지나는 동안 보호받지 않은 상태로 노출되면 디버프가 발생한다.
- 디버프는 허기 감소 가속과 체력 손실 등 실질적인 위험을 만든다.
- 현재 노출 여부와 감염된 디버프 상태를 구분한다.
- 상태 아이콘과 짧은 설명으로 원인과 치료 방법을 알린다.
- 대피하거나 방독면을 착용하면 새 노출을 막는다.
- 이미 발생한 디버프가 치료되는지와 단순히 노출만 차단되는지를 명확하게 구분한다.
- 우유로 치료한 뒤에도 계속 노출되면 다시 디버프에 걸릴 수 있다.
- 매 프레임 피해를 중복 계산하지 않는다.
- 기존 독 상태와 방사능 디버프를 혼동하지 않는다.

### 권장 기본값

- 보호 없이 2초 연속 노출되면 방사능 디버프 발생.
- 디버프 지속 시간 30초.
- 체력 초당 1 감소.
- 허기 초당 0.5 추가 감소.
- 계속 노출되면 지속 시간만 갱신하고 피해 배율은 중첩하지 않는다.
- 보호 장소에 들어가면 노출 누적은 초기화하지만 이미 발생한 디버프는 남은 시간 동안 지속한다.
- 우유를 마시면 방사능 디버프와 현재 노출 누적을 즉시 제거한다.
- 다시 야외에 노출되면 2초 후 재발할 수 있다.

정확한 수치를 변경할 경우 초기 생존 난이도와 기존 체력·허기 감소량을 함께 검토하고 최종값을 보고한다.

## 11. 방사능 먼지를 막는 실내·지하 판정

### 확정 요구사항

- 단순히 머리 위 블록 하나가 있다는 이유로 보호되지 않게 한다.
- 나무나 나뭇잎 아래를 완전한 방사능 대피소로 취급하지 않는다.
- 외부와 연결되지 않은 막힌 공간은 보호한다.
- 닫힌 문은 차단하고, 열린 문이나 벽의 구멍은 연결된 통로로 취급한다.
- 폐광도 외부 연결 상태에 따라 판정한다. 폐광이라는 이름만으로 무조건 보호하지 않는다.
- 플레이어가 만든 집에도 동일한 규칙을 적용한다.
- 채굴·설치·문 개폐 직후 보호 상태를 갱신한다.
- 화면 밝기, 미노타우르스 직사광선, 방사능 대피 판정을 별개의 개념으로 유지한다.
- 청크가 로드되지 않았다는 이유만으로 빈 공간 또는 막힌 벽이라고 오판하지 않는다.

### 구현 지침

외부 공기와의 연결 여부 또는 동등한 방식으로 실내를 판정한다.

월드 전체를 매 프레임 탐색하지 않는다. 이벤트 시작·주변 지형 변경·문 개폐 등에 맞춰 캐시와 제한된 갱신을 사용한다. 판정이 아직 계산 중일 때 처리 방식도 명확하게 정한다.

## 12. 폐광 보상 방독면

### 확정 요구사항

- 방독면 아이템을 추가한다.
- 폐광 보급 상자에서 얻을 수 있게 한다.
- 가방에 보유한 것과 실제 착용한 것을 구분한다.
- 착용 중에는 방사능 먼지 노출을 막는다.
- 이미 생긴 방사능 디버프를 방독면 착용만으로 즉시 치료하지 않는다.
- 착용 상태를 UI로 확인할 수 있게 한다.
- 착용·해제·버리기·사망·저장·재접속에서 복제나 유실이 없어야 한다.
- 일반 보급 상자와 폐광 보급 상자의 출처를 구분해 보상을 적용한다.
- 같은 좌표에 플레이어가 상자를 다시 설치했다고 폐광 보상이 새로 생기지 않게 한다.

### 권장 1차 범위

- 방독면은 비중첩 아이템으로 한다.
- 별도 방어구 전체 시스템은 만들지 않고 방독면 착용 상태만 추가한다.
- 초기 버전에서는 내구도와 필터 소모를 넣지 않는다.
- 폐광 보급 상자마다 20% 확률로 방독면 1개를 추첨하는 것을 기본값으로 한다.
- 한 개를 얻지 못해도 실내 대피로 생존할 수 있어야 한다.
- 사망 시 기존 소지품 사망 처리 규칙을 따르되, 착용한 방독면도 빠짐없이 한 번만 처리한다.

## 13. 지상 호수·웅덩이와 물가 모래

### 확정 요구사항

- 지상에도 물을 얻을 수 있는 호수와 작은 웅덩이를 생성한다.
- 너무 자주 생성하지 않는다.
- 분지 등 물이 고일 만한 낮은 지형과 결합한다.
- 시작 지점이 물속에 생기지 않는다.
- 수역과 구조물이 부자연스럽게 겹치지 않는다.
- 물가 일부에 모래 지형을 생성한다.
- 모든 물가를 동일한 폭의 모래 테두리로 감싸지 말고 흙·돌과 자연스럽게 섞는다.
- 모래는 채굴해 아이템으로 얻는다.
- 유리 제작에 사용할 수 있다.
- 물과 모래가 청크 경계에서 끊기지 않게 한다.

### 권장 기본값

현재 월드 크기에서 지상 수원은 총 2~4곳 정도로 시작하고, 작은 웅덩이가 큰 호수보다 흔하게 한다.

모래의 낙하 물리는 이번 필수 요구사항이 아니므로 별도 필요가 없다면 추가하지 않는다.

## 14. 모래 → 유리 → 빈 물병 제작

### 확정 요구사항

제작 흐름은 다음과 같다.

1. 물가에서 모래 채굴.
2. 모래를 가열·제련해 유리 제작.
3. 유리로 빈 물병 제작.

- 모래·유리·빈 물병을 데이터로 정의한다.
- 레시피를 코드에 하드코딩하지 않는다.
- 기존 제작 시간·시설 접근·결과물 공간 부족 처리와 연결한다.
- 유리와 물병에 희귀한 철을 요구하지 않는다.
- 아이콘은 모래·유리·빈 병을 구별할 수 있게 한다.

### 권장 기본값

별도 용광로 시스템을 추가하지 않는 최소 범위로 다음을 사용한다.

- 연료가 켜진 모닥불: 모래 2개 → 유리 1개, 5초.
- 작업대: 유리 3개 → 빈 물병 3개.
- 모래를 얻으면 유리 제작법 해금.
- 유리를 얻으면 물병 제작법 해금.
- 모닥불 제작 목록에 음식 외 유리도 표시되므로 제목과 안내를 적절하게 변경한다.
- 연료가 떨어지면 제련도 일시정지하고 재투입 후 이어진다.

이는 게임 편의를 위한 제작 규칙이다. 별도 제련 시설을 선택한다면 추가 범위와 이유를 먼저 명확히 한다.

## 15. 물병으로 물 담기

### 확정 요구사항

- 빈 물병을 들고 물을 조준하면 상황별 ‘물 담기’ 버튼이 나타난다.
- 빈 물병 1개를 소비하고 물이 든 병 1개를 얻는다.
- 지상 수원과 지하 수원 모두 사용할 수 있다.
- 사거리와 벽 가림 판정을 적용한다.
- 물병을 선택했다는 이유만으로 조준 패드에 손을 올리는 순간 자동으로 물을 담지 않는다.
- 모바일은 명시적인 상황별 버튼을 사용한다.
- PC에서도 채굴·설치와 충돌하지 않는 명시적인 상호작용으로 처리한다.
- 인벤토리 공간이 부족할 때 빈 병만 사라지지 않게 한다.
- 빈 병 소비와 결과물 생성은 하나의 거래로 처리한다.
- 물을 마시면 빈 병을 돌려준다.
- 빈 병을 돌려줄 공간이 없으면 안전한 드롭 등 기존 규칙으로 보존한다.

### 권장 기본값

- 별도 갈증 게이지는 이번에 추가하지 않는다.
- 물은 허기·체력을 회복하거나 방사능을 치료하지 않는다.
- 대신 기존 일반 독 상태를 완화하는 효과를 선택할 수 있으나, 확정하지 않았다면 효과를 임의로 넣지 않는다.
- 물의 초기 용도는 채집·보관·마시기와 향후 제작 재료 기반으로 제한해도 된다.
- 물이 특별한 효과가 없다면 설명에 솔직하게 표시한다.
- 이번 버전에서는 깨끗한 물·오염된 물을 나누지 않는다.
- 병 1개로 물을 담아도 수원은 줄어들지 않는 방식을 기본으로 한다.

물의 음용 효과는 미확정 사항이므로 최종 적용 여부를 결과 보고에 명확하게 적는다.

---

## 16. 물병으로 소에게서 우유 얻기

### 확정 요구사항

- 빈 물병을 들고 살아 있는 소를 조준하면 ‘우유 짜기’ 버튼이 나타난다.
- 빈 물병 1개를 소비하고 우유병 1개를 얻는다.
- 물이 든 병으로 바로 우유를 짜지 않는다.
- 소의 몸을 정확히 조준하고 사거리·벽 가림 조건을 만족해야 한다.
- 착유 상호작용이 소 공격과 동시에 실행되지 않게 한다.
- 죽은 소에게서 우유를 얻을 수 없다.
- 우유를 마시면 방사능 디버프를 치료한다.
- 마신 뒤 빈 물병을 반환한다.
- 디버프 치료와 체력 회복을 혼동하지 않는다. 체력이 즉시 전부 회복되는 효과는 요구사항이 아니다.

### 권장 기본값

- 같은 소는 게임 진행 시간 60초에 한 번 착유 가능.
- 쿨다운 중에는 남은 시간을 안내한다.
- 일시정지·앱 비활성 중에는 쿨다운이 진행되지 않는다.
- 재접속으로 즉시 반복 착유가 가능해지지 않도록 상태를 관리한다.
- 우유의 핵심 효과는 방사능 치료이며, 추가 허기·체력 회복은 기본적으로 넣지 않는다.

## 17. 상호작용 입력 통합

### 확정 요구사항

새 기능을 추가하면서 상시 버튼을 무작정 늘리지 않는다.

기존 상황별 버튼을 사용한다.

- 문: 열기·닫기.
- 침대: 잠자기.
- 상자: 열기.
- 작업대·모닥불: 사용.
- 치와와: 고기 주기.
- 물 + 빈 병: 물 담기.
- 소 + 빈 병: 우유 짜기.

### 판정 원칙

- 조준 대상과 선택 아이템에 따라 동작을 명확하게 결정한다.
- 블록 뒤 몬스터를 잘못 선택하지 않는다.
- 소에게 우유를 짜려다 공격하거나, 물을 담으려다 블록을 설치하지 않는다.
- 상호작용 버튼을 누를 때 기존 채굴·공격 진행을 적절히 중단한다.
- 다른 손가락의 이동 입력이 조준점 변경으로 전달되지 않는다.
- 조준 패드 이동과 상황별 버튼 위치가 겹치거나 화면 밖으로 나가지 않게 한다.
- 버튼을 누르고 있는 도중 대상이 바뀌었을 때 엉뚱한 대상에게 동작하지 않도록 한다.

## 18. 생성 버전과 저장 호환

### 확정 요구사항

- 기존 블록 numericId와 아이템 ID를 유지한다.
- 새 데이터는 기존 ID 뒤에 추가한다.
- 새 지형 생성은 새로운 생성 버전으로 구분한다.
- 기존 저장 월드를 새 지형으로 강제 재생성하지 않는다.
- 기존 건축물·상자·연료·문·침대·아이템·길들인 치와와를 초기화하지 않는다.
- 새 지형 변경은 새 월드부터 적용하는 것을 기본으로 한다.
- 기존 저장에도 적용 가능한 기능과 새 월드가 필요한 기능을 구분해 안내한다.

저장해야 할 신규 상태:
- 누적 게임 시간과 경과 일수.
- 방사능 먼지 일정과 진행 상태.
- 플레이어 방사능 디버프.
- 방독면 착용 상태.
- 필요한 구조물 출처·보급 상자 정보.
- 우유 착유 쿨다운을 유지하는 데 필요한 상태.
- 기존 물·지형 변경 저장과 연동되는 데이터.

잘못된 데이터는 파일명·필드명 또는 저장 항목명을 포함해 오류를 표시한다.

## 19. 성능과 구현 제한

- 월드 생성은 기존 Web Worker 구조를 유지한다.
- 청크 등록과 로드 상한을 깨뜨리지 않는다.
- 협곡·수역·폐광·특별 장소의 결정적 생성과 겹침 처리를 구현한다.
- 대피소 판정과 물 관련 처리를 매 프레임 전체 월드 탐색으로 구현하지 않는다.
- 파티클과 동적 오브젝트 수를 제한한다.
- 새 라이브러리나 엔진 교체는 꼭 필요한 경우에만 검토한다.
- 이번 요청과 무관한 보스·퀘스트·농사·번식·전체 장비 시스템·무한 월드는 추가하지 않는다.

## 20. 최소 테스트

검사는 변경한 핵심 동작에 집중하고 불필요하게 반복하지 않는다. 실제 실행한 검사와 코드 검토만 한 항목을 구분한다.

### 월드 생성
- 새 게임에서 좌우 양방향 이동 가능.
- 시작 위치가 안전함.
- 같은 시드의 지형·협곡·물·구조물 일치.
- 청크 경계에서 협곡·호수·폐광이 끊기지 않음.
- 물과 구조물이 기반암을 침범하지 않음.
- 기존 저장 지형이 변하지 않음.

### 구조물·보상
- 폐광 여러 방과 통로 연결.
- 지상 특별 장소의 낮은 생성 빈도.
- 보급 상자의 철 보상.
- 폐광 방독면 보상의 출처 구분.
- 보급 상자 반복 조작으로 보상 복제 없음.

### 방사능
- 첫 3일 준비 기간.
- 예고·시작·종료·다음 일정.
- 일시정지·재접속·수면 후 시간 일관성.
- 막힌 방 보호, 열린 문·구멍 노출.
- 머리 위 블록 하나만으로 보호되지 않음.
- 방독면 소지와 착용 구분.
- 디버프 중첩 방지.
- 우유 치료와 재노출.

### 물병·제작
- 모래→유리→빈 병 제작.
- 연료 소진 시 제련 정지와 재개.
- 물 담기와 우유 짜기에서 정확히 1개씩 교환.
- 가득 찬 인벤토리에서 아이템 유실 없음.
- 물·우유 사용 후 빈 병 반환.
- 벽 너머 상호작용 차단.
- 착유 쿨다운과 재접속 처리.

### 치와와·입력
- 적대·온순 외형 차이.
- 먹이 1개 소비와 해당 개체만 진정.
- 저장 후 온순 외형과 행동 유지.
- 모바일 이동·점프·조준·상호작용 동시 입력.
- 새 상호작용이 채굴·공격·설치를 잘못 실행하지 않음.
- 의도하지 않은 줌인 없음.
