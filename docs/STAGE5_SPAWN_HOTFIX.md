# 스폰 양방향 이동 긴급 수정 — 생성 버전 7

작성일: 2026-10-15. 기준 배포본: `ganadi_stage5_update.zip` (5단계 작업). 게임 공개 사이트는 수정하지 않음.

## 문제와 실제 재현

- 2단계 중앙 스폰 구현은 출발 지점 2칸의 바닥·머리 공간만 확인했음.
- 근처 나무줄기·높아진 지형·이전 구조물 때문에 바로 왼쪽/오른쪽 통로가 막힐 수 있었음.
- **실제 게임 번들에서 추출한 플레이어 충돌·이동 클래스**로 40개 v6 시드를 보행 테스트한 결과, 33개 시드에서 출발점 기준 어느 한쪽이 64px 이내에 막힘. 일부는 왼쪽 3px 이동 후 정지.
- 기존 테스트는 스폰 좌표의 중앙성·바닥만 검사하여 실제 이동 가능성 결함을 발견하지 못함.

## 해결

- 신규 월드는 `generationVersion:7`; 기존 v1~v6의 셀 생성 결과를 변경하지 않음.
- 중앙에서 40타일 이내의 후보 중 구조물·물과 충분히 떨어진 곳을 고르고, 자연스러운 기존 지형을 우선 선택.
- 시작 지점 좌우 **각 6타일**만 보행 가능한 작은 빈터를 확보하고 바깥쪽 4타일에서 기존 지형과 부드럽게 연결.
- 통로의 장애 나무줄기와 하부 잎만 제거. 주변 대부분의 지형·나무·구조물·호수·광물은 변경하지 않음.
- 생성 버전 1~6과 기존 저장 버전 2는 그대로 유지. 기존 세이브 위치는 강제로 이동시키지 않음.
- 4·5단계 기능 및 전투 수치·키보드/모바일 입력·자원 정의·저장 데이터를 변경하지 않음.

## 자동 검사

- 기존 자동 테스트 44건과 신규 4건: `npm test` **48/48 통과**.
- 신규 생성 120개 시드를 대상으로 실제 게임 물리 이동 클래스로 점프하지 않고 각각 좌우 90px 이상 보행 확인.
- 6개 세대(v1~v6)의 셀 배열 해시가 수정 전 5단계 ZIP과 바이트 단위로 일치.
- 동일 v7 시드의 결과 재현, 기존 폐허 구조물의 블록 보존 확인.
- 브라우저·Android 실제 화면 조작은 이 실행 환경에서 검증하지 못함. 자동 검사 성공을 실기 성공이라고 보고하지 않음.

## 주의: 기존 세이브

- 생성 버전 1~6으로 이미 저장한 월드는 **원래 지형 그대로 유지**됩니다. 해당 월드의 막힌 지형도 자동으로 깎거나 이동시키지 않습니다.
- **새 게임 시작**을 선택해야 생성 버전 7이 적용됩니다. 이어하기는 저장된 생성 버전을 그대로 사용합니다.
- 저장 세이브를 삭제할 필요는 없습니다. 기존 세이브를 유지하면서 새로운 시드로 시작하면 저장 슬롯 덮어쓰기 동작이 있을 수 있으므로 먼저 백업하는 것을 권장합니다.
