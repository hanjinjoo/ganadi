# 6단계 — 치와와 표정, 상황별 상호작용, 초기 로딩 긴급 수정

기준 배포본: 5단계 스폰 핫픽스 v7. 1~5단계의 기능과 별도로, 사용자가 공개 배포본에서 보고한 `resetPlayer(): Cannot read properties of undefined (reading 'x')` 오류를 긴급 보완한 내용을 포함한다.

## 완료한 코드 변경

1. **초기 로딩 오류 복구** — `assets/index-expansion.js`의 `resetPlayer()`에서 월드 Worker 스냅샷의 `spawn`이 없거나 불완전한 경우 지형 정보로 안전한 초기 좌표를 탐색. 기존 정상 좌표와 v1~v3 시작점은 유지. 임의로 기존 세이브를 옮기거나 지형을 다시 생성하지 않음. v4~v7 지형 해시 유지. 정적/시뮬레이션 검증만 완료.
2. **치와와 픽셀 외형** — `assets/fauna-runtime.js`의 `chihuahuaPixels()`에서 큰 직립 귀, 둥근 머리, 짧은 주둥이, 가는 다리, 꼬리를 표현. 적대 상태에는 찡그린 눈·이빨, 온순 상태에는 편안한 눈·다문 입·목줄을 표현. 피격 시 붉은 몸색 표시를 유지하면서 눈과 입 표현까지 전체가 빨갛게 덮이지 않도록 분리. 물리 몸 판정·공격력·체력·먹이·저장·공격 AI 변경 없음.
3. **상황별 버튼 안전성** — `assets/station-place.js`와 신규 `assets/stage6-ui.js`에서 눌렀던 대상과 최종 실행 대상의 정체성을 비교. 치와와는 **개체 객체 동일성**까지 검사하며 먹이 주기에서 최종 대상 객체를 다시 확인. 물·소는 기존 4단계 판정과 연동. 조작 버튼 배치는 조준 패드·조이스틱·점프·공격 버튼·핫바와 화면 경계를 고려해 계산하고, 적합한 공간이 없다면 화면 바깥으로 밀어내지 않고 숨김. 기존 터치 포인터·이동·공격·설치 입력은 유지.

## 보존 정책

- 세계 생성: 신규 v7 그대로, 기존 v1~v6 결과 변경 없음.
- 저장: 기존 스키마 v2 유지, `stage4`, `stage5`, `fauna` 필드 구조 변경 없음.
- 핵심 몬스터 수치, 기존 문·침대·상자, 방사능·제작·착유 기능, PNG/SVG/오디오 리소스 교체 없음.
- **원격 GitHub Pages 배포 없음** — 사용자가 7단계 완료 후 한 번에 배포한다고 결정함.

## 검사 결과

- `npm test`: 56/56 통과 (기존 50 + 신규 6). `spawn` 누락 35개 시드 복구 및 구형 지형 해시 회귀 포함.
- 별도 정적 리소스/구문 검사와 HTTP 응답 검사 (수치 및 결과는 최종 보고 기록 참조).
- **실제 Chromium/Android 플레이 미검증**. 이 환경의 Chromium은 `http://127.0.0.1/`과 `file://` 탐색을 `ERR_BLOCKED_BY_ADMINISTRATOR`로 차단한다. 따라서 실제 UI 겹침, 멀티터치, 사용자 세이브 불러오기, 게임 전체 로딩 종료를 실기 완료라고 선언하지 않음.
- `assets/audio/`의 기존 `.ogg` 누락(공개 사이트 404)은 이번 6단계 수정 범위 밖으로 남아 있음. 누락된 오디오 파일을 임의로 대체하지 않음.

## 7단계 전 실기 확인 요청

1. 배포 없이 로컬 ZIP 압축 해제 후 PowerShell에서 `python -m http.server 8000` 실행.
2. 개발자 도구 Console을 열고 **새 게임**으로 `청크 준비 중`을 벗어나는지, `undefined.x` 오류가 없는지 확인.
3. 새 v7 월드 중앙에서 좌우 6타일 보행, 점프·조준 패드·공격의 멀티터치 확인.
4. 같은 개체에 고기 1개를 주면 온순 표정으로 바뀌고 다른 치와와는 적대 상태로 남는지 확인. 저장 후 이어하기에서 유지 확인.
5. 소 착유·물 담기·문 열기·상자 열기의 상황별 버튼을 누른 채 조준 대상을 바꿀 경우 다른 대상에 잘못 실행되지 않는지 확인.
6. 오디오 `.ogg` HTTP 404는 별도 이슈로 분류.
