# 4단계 설계·구현 기록 — 물가 모래, 병 제작, 물·우유

**기준:** 3단계 배포 ZIP, DEVELOPMENT_SPEC.txt §§13–17 및 §18. **GitHub Pages 미배포.**

## 생성 버전 및 기존 월드 보존

- 새 월드 생성 버전 **6**. 기존 1~5 생성기 분기는 변경하지 않으며, 버전 1~3 해시와 4~5 별도 기준 해시를 회귀 검사한다.
- 새 월드는 2단계 물 수역 주변의 일부 흙을 **모래(numericId 24)**로 대체한다. 같은 시드에서 동일하고, 기존 구조물과 기반암을 지킨다.
- 1~5 버전 저장을 불러올 때는 **새 모래 지형을 강제로 생성하지 않는다**. 해당 월드에서 물병 기능을 쓰려면 모래 아이템을 따로 확보해야 한다.
- 기존 블록 ID 1~23, 기존 아이템 ID와 레시피 ID, 3단계 보급 상자/저장 규칙 유지.
- 기존 물 타일은 고체가 아니며 채굴 아이템으로 얻는 대상이 아니다. 기본 아이템 검증기에 물 타일 예외를 등록해 기존 2단계 로딩 오류 가능성을 수정했다.

## 아이템/제작법

| ID | 표시 이름 | 종류 | 효과 |
|---|---|---|---|
| sand | 모래 | 블록 | 물가 채굴 가능, 블록으로 설치 가능 |
| glass | 유리 | 재료 | 모래 제련 결과 |
| empty_bottle | 빈 물병 | 재료 | 물 담기 및 착유에 소비 |
| water_bottle | 물병 | 음식 취급 | 마시면 빈 물병 반환, 체력/허기/방사능 효과 없음 |
| milk_bottle | 우유병 | 음식 취급 | 마시면 빈 물병 반환, 방사능 치료는 5단계에서 구현 |

- 켜진 모닥불: 모래 2개 → 유리 1개, **5초**. 기존 연료 소진 시 제작 정지/재개 로직을 재사용한다.
- 작업대: 유리 3개 → 빈 물병 3개, 즉시 제작.
- 레시피 데이터는 `data/recipes.json`에 추가하고 제작 시간/재료/결과 공간 검사는 기존 코드를 사용한다.
- 인벤토리 아이콘 5개 및 모래 블록 텍스처 1개 신규. 기존 이미지 삭제 없음.

## 명시적 상호작용

- **모바일:** 기존 상황별 버튼만 사용. 빈 병을 선택하고 물 타일이나 살아 있는 소를 조준하면 `물 담기`/`우유 짜기` 표기.
- **PC:** 빈 병 선택 후 조준하고 `E` 키를 눌러 명시적으로 실행. 마시기는 기존 먹기 버튼 또는 `F` 키.
- 소와 물 모두 플레이어에서 **48px(3타일)** 내, 막힌 벽 통과 불가. 소는 몸체 실제 픽셀 범위를 지정해야 하며 죽은 소는 불가.
- `empty_bottle` 선택 중의 **자동 동물 공격**을 억제하여 착유 중 우발적 공격 방지. 나머지 무기·블록 공격 경로는 유지.
- 조준 패드를 움직인 것만으로 물 담기/착유가 실행되지 않는다. 버튼 누름과 클릭 직전에 대상 동일성을 다시 검증한다.
- `exchangeOne`은 소모·획득을 동기적 1:1 트랜잭션으로 처리. 결과 공간이 전혀 없으면 빈 병을 소비하지 않는다.
- 물/우유를 마신 후 빈 병을 반환. 공간이 없는 경우 기존 바닥 드롭(대기 큐 보존)에 반환하여 유실 방지.
- 물은 고정 수원으로 유지되며 물병에 담아도 감소하지 않는다. 갈증·복잡 유체·물 오염 상태를 추가하지 않는다.

## 착유 재사용 제한 및 저장

- 같은 활성 소에게는 **게임 진행 시간 60초**마다 착유 가능. 일시정지·비활성 시간에 타이머가 진행되지 않는다.
- 기존 소 개체는 저장되지 않는 구조여서, 기존 월드에서 각 소의 영구 GUID를 복원할 수 없다. 대신 활성 개체는 `WeakMap`으로 구분하고, 재접속 후 같은 지역에 즉시 재착유하는 것을 막기 위해 기존 스폰 좌표 주변 3타일의 제한 기록을 사용한다. **가까운 다른 소도 대기 제한을 받을 수 있는 1차 타협안**이다. 완전한 소별 재접속 추적을 원한다면 개체 영속화가 필요하다.
- 저장은 기존 `version:2` 유지, 선택적 `stage4:{version:1,milkingCooldowns:[{x,y,until}]}` 확장. 미존재 구저장은 빈 목록으로 이주. 잘못된 필드는 필드명을 포함해 거부.
- `until`은 누적 게임 시간(초)을 기준으로 계산하고, 저장/복원/수면 뒤에도 같은 기준을 따른다.
- 이후 5단계 방사능 치료는 `scene.stage4.onDrinkMilk` 훅에 연결할 수 있도록 마련했다. **치료 자체는 아직 구현하지 않았다.**

## 검증 범위 및 잔여 위험

- `npm test`: 4단계 추가 검사와 1~3단계 회귀 검사 전부 통과.
- 실제 프로덕션 아이템/레시피/세이브 검증 코드를 VM에서 추출해 신규 데이터가 통과하는지 확인.
- 버전1~5 생성 결과, 30시드 신규 수역/모래, 가방 공간, 물 담기, 착유, 벽·거리, 쿨다운, 저장 필드 테스트.
- 실기 Android/Chrome 입력·조작감·저장 파일 복원은 **미검증**. Chromium의 localhost 접속이 `ERR_BLOCKED_BY_ADMINISTRATOR`로 차단됨.
- GitHub Pages 배포 **하지 않음**. 7단계에서 통합 실기 확인 후 배포 예정.
