# 3단계 설계 및 작업 보고 — 폐광·특별 장소·보급 상자

기준: `DEVELOPMENT_SPEC.txt` 2항·6항·7항·18항·19항·20항. 작업 승인: 사용자 2026-10-15.

## 구현 범위

1. **기존 저장 보호 / 생성 버전 5**: 1~3 생성 결과 고정, 2단계에서 생성한 버전 4 지형도 그대로 보존. 버전 5 신규 월드에만 3단계 구조물과 배치 적용. 기존 생성 버전 4로 저장된 월드를 강제로 버전 5로 바꾸지 않는다.
2. **폐광**: 기존 `old_mine` 20×8 방을 중심으로 좌우 갱도, 동쪽 수직 통로, 위쪽 창고, 아래쪽 보상실 등 **총 6개 모듈**. 수평 연결부와 나무 지지대, 채굴 가능한 잔해, 번갈아 놓인 발판, **폐광 보급 상자 총 4개**(원래 2 + 추가 2). 이전 광산 템플릿은 다른 세대에서 변경하지 않는다.
3. **특별 장소**: 각 월드에 **2~4곳**. 기존 폐허·물·새 월드 중앙 스폰을 피해서 거리 제한을 적용한다. 야영지(목재+모닥불), 오두막(지붕+두 칸 문), 무너진 탑(부분 벽+수직 발판). 시드별로 매 종류가 반드시 등장하는 것은 아니다. 보급 상자는 해당 장소에 모두 고정 배치되지 않으며, 일부 장소에만 확률적으로 배치한다.
4. **보급 상자 철**: `data/loot_tables.json`의 일반 상자에 `scrap_metal` 1개 독립 **10%**, 기존 구리 30% 및 통조림·횃불·나무 조각 보존. 맨 뒤에 철 항목을 추가해 기존 아이템 추첨용 난수 호출 순서를 보존한다.
5. **철 광석 보상**: `scrap_ore`의 기존 전리품 테이블이 `copper`를 제공하던 실제 데이터 문제 수정. 블록 데이터에서 이미 설정된 `scrap_metal`을 드롭하도록 전리품 테이블을 고쳤으며, 아이템 ID는 바꾸지 않았다.
6. **보상 복제 방지 / 출처 구분**: Worker가 원래 생성된 보급 상자 좌표·출처(`mine`/`surface`)를 메타데이터로 전송. 실제 채굴 보상은 생성 위치에 한 번만 제공하며, 사용자가 다시 설치한 상자는 보상을 새로 생성하지 않는다. 수령 좌표는 `lootClaims`에 저장. 기존 저장 포맷 `version:2`의 선택적 추가 필드이다.
7. **구세이브 추정 이주**: `lootClaims`가 없는 기존 세이브에서는 `chunkDiffs`가 자연 생성 상자 자리를 변경한 경우 해당 보상은 이미 수령한 것으로 간주해 복제 위험을 낮춘다. *이전 세이브에서 이미 보상을 수령한 뒤 같은 좌표에 상자를 다시 설치해 원본 지형과 구분이 불가능해진 경우, 과거 수령을 완전히 복원할 근거가 없다는 한계가 있다.*

## 결정적 생성 및 물·지형 충돌

- 구조물은 v4 지형·협곡·정적 물 생성 이후, 월드 전체 타일 배열 위에서 일괄 한 번만 생성한다. 각 청크는 생성 완료된 동일 배열을 잘라 전송하므로 청크 경계에서 구조물이 이어진다.
- 기존 폐광의 원형과 이미 존재하는 보급 상자 좌표는 보존한다. 신규 모듈의 경계에서 암석, 기존 동굴, 일부 고정된 물을 덮어 쓸 수 있으며 **구조물이 자신의 작은 점유 영역에서는 우선**한다. 동굴 전체나 협곡 전체를 삭제하지 않는다.
- 지상 특별 장소는 기존 폐허·지상 호수·스폰에서 거리를 두고, 좁은 건물 바닥만 평탄화한다. 세계 전체의 높이 또는 경계 기반암은 변경하지 않는다.
- 보급 상자 출처는 '원래 월드 생성 시 실제로 배치된 보급 상자'에만 부여한다. 추후 방독면(5단계) 추첨은 `source === 'mine'`에서만 가능하도록 설계한다. **3단계에는 방독면 아이템/효과/추첨이 없다.**
- 캠프의 모닥불은 원래 연료 관리 시스템을 사용한다. 자동 무한 연료는 지급하지 않는다.
- `world.heights`는 신규 지상 특별 장소의 좁은 바닥 범위만 갱신하며 그 밖의 지형은 v4 알고리즘을 사용한다.

## 수정 파일

- `assets/structures-v5.js`: **신규** v5 폐광·특별 장소·상자 출처 생성.
- `assets/world.worker-expansion.js`: v5 전용 생성 모듈 연결과 메타데이터(`supplyOrigins`, `stage3`) 전달.
- `assets/clock-compat.js`: 지원 생성 버전 상한 5 (기존 1~4도 그대로 지원).
- `assets/index-expansion.js`: 신규 월드 버전 5; 보급 상자 출처·1회 지급·저장/복원; 기존 v2 저장 검증의 선택적 필드 추가.
- `data/loot_tables.json`: 철 10% 및 철 광석 드롭 수정.
- `tests/stage1.test.mjs`, `tests/terrain-v4.test.mjs`: 기존 회귀 테스트의 기본 신규 버전 기대값만 보정.
- `tests/stage3.test.mjs`: **신규** 결정적 생성·연결·출처·확률·구세이브 보전 등 테스트.
- `package.json`: 테스트 스크립트에 신규 파일 포함.
- `PROGRESS.md`, `README_STAGE3_POWERSHELL.md`: 문서 갱신.

## 검사 결과와 한계

- Node 내장 자동 테스트 **24/24 통과** (`npm test`).
- 새 버전 5 구조물 **30개 다른 시드**에서 다중 모듈 연결·출처·배치 간격을 확인. v1~v3 지형 해시와 v4 지형 해시 4건을 과거 단계 원본 ZIP과 대조해 일치함.
- 900개 결정적 보급 상자 추첨에서 기존 보상들이 바뀌지 않음을 검사하고 철의 독립 10% 설정이 작동함을 통계적으로 확인.
- JavaScript/MJS 구문 검사 통과, JSON 파싱 정상. 기존 ZIP 파일 88개 중 80개는 바이트 단위 그대로이며, 기존 사진·사운드·텍스처·UI·조작 코드 미변경.
- **실제 브라우저/Android 플레이 검증은 미실시.** 현재 실행 환경에서는 로컬 HTTP 접속이 거부됨. 사용자가 실제 플레이로 확인하기 전에는 사용자 인터페이스와 발판 조작감을 검증 완료라고 선언하지 않는다.
- 이번 변경은 TypeScript 원본 빌드가 아니라 기존 배포 JS/Worker의 확장이며, 정적 배포 ZIP으로 납품한다. GitHub Pages 업로드하지 않음.

## 4단계 이후 인계 사항

- 4단계 제작법·상호작용·착유는 현재 코드를 그대로 바탕으로 추가한다. 아이템·블록 ID는 뒤에만 추가한다.
- 5단계 방독면 보상은 `snapshot.supplyOrigins`의 `mine` 출처를 확인한 다음, `lootClaims`와 결합해 1회만 추첨한다.
- 사용자 모바일/PC 실제 조작으로 광산 승강로, 탑 발판, 오두막 문 작동, 저장·재접속을 확인해야 한다.
